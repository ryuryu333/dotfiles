---
name: cause-investigation
description: 失敗や、想定と違う結果の原因を調べるときに読む。
---

1. 期待していた動作を確かめる。
2. 期待していた動作について、user と認識をそろえる。
3. 実際に起きたことを観察する。事実だけを整理し、推測は入れない。
4. 何が、どのような仕組みで起きたかを考察する。推測してよいが、事実とは分けて示す。現象を言い直すだけでは、考察にあたらない。
5. 仮説を user に共有する。対策は含めない。
6. user との議論の中で、追加の調査や実験をして仮説を検証し、絞り込む。
7. user が仮説の確定を告げたら、次に進む。
8. 確定した仮説から対策を考える。ここからは、通常の作業依頼と同じ流れで進める。
