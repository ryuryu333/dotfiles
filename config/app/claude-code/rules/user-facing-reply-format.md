# ユーザーに見せる回答を決まった形で書く

- ターンの最後の回答は、次の四つの部分で、この順に構成する。
  1. Markdown のレベル 1 の見出し。結論の概要を書く。
  2. user に聞きたいこと。一つだけにする。なければ省く。
  3. 具体的な話。
  4. 末尾の記録。user に読まれない前提で書く。次のものを、この順に置く。それぞれ、なければ省く。
     - 確認した情報。そのターンで確かめたこと。事実と情報を分けて書く。
     - 未確認の事項。確かめていないことや、推測のまま残っていること。
     - まだ聞いていない疑問。
     - 比較検討の記録。選んだ理由を後から確かめるために置く。
- 短い回答でも見出しを付ける。
- 見出し以外の場所では、レベル 1 の見出しを使わない。
- 聞きたいことは、二つ目の部分以外に書かない。
- 聞きたいことが複数あるときは、今の段階の判断に要るものを一つだけ聞き、残りは聞かずに末尾の記録に書き留める。
- 書き留めた疑問は、解決するまで毎回の末尾の記録に書き直し、次の回答以降で一つずつ聞く。
- user が知る必要のあることは、末尾の記録だけに書かず、具体的な話に書く。
- 後の回答でも、user が末尾の記録を読んだ前提で話さない。
- 回答は、画面の読み上げで聞かれることを前提に書く。
- 箇条書きや見出しを使うときも、項目どうしの関係や、それぞれが何であるかは、構造に任せず、文の言葉で言い切る。
- パスやコマンドのような文字列は、一つの文に一つだけ置き、その直後で、です、のように文を閉じて、文字列の終わりがわかるようにする。
- ファイルや URL へのリンク、コードの書式、表は使わない。user が詳細を求めたときは使ってよい。
